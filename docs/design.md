## 为什么编译验证放在浏览器侧

写入前要求 shader 真的能编译，这件事**只能由浏览器做**：

| 层 | 手段 | 拦什么 |
|---|---|---|
| 浏览器（发布前） | 本机 WebGL2/ANGLE 编译 + 链接成功（`lastCompiledCode`） | 语法错、未定义标识符、链接失败 —— 零误判 |
| 服务端（写入前） | `validateGlslShape()`：只在「必定编译不过」时拒 | 非 GLSL 载荷、与包装器抢名字/抢指令的写法 |

服务端不做真编译，原因有两条，第二条是决定性的：

1. Serverless 没有 GPU，跑不了 WebGL2。硬塞 Playwright + Chromium 进函数包是几百 MB、冷启动数秒、且只有 SwiftShader 软件渲染 —— 不能放在请求路径上。
2. 唯一可行的 `glslangValidator` 二进制（6.7 MB）**会误杀合法 shader**。仓库自带的 `70s-melt-color` 在真实 WebGL2/ANGLE 下编译 + 链接 + 渲染全部通过，glslang 却判它失败（`'mediump'` 重载精度）。`scripts/lib/glsl-backend-glslang.js` 里的 `BROWSER_DIVERGENT` 就是为此存在的，而那张表是**实测攒出来的、必然不完整** —— 每一条都对应一次「某个 shader 被错杀」。拿它当写入门槛，等于把尚未发现的分歧全部变成「用户无法发布且无处申诉」。

这个成本差决定了一切：**CI 里误报很便宜**（维护者看一眼、浏览器里验证、加一条）；**用户侧误报很贵**（他只会觉得这个站坏了）。所以同一个误报，在 `npm run glsl:check` 里可以接受，在发布接口里不能。

于是服务端的形态校验**只收「无论哪个实现都必定失败」的特征**：缺 `mainImage`、自带 `#version`、重复定义 `void main()`、含 `script` 标签。判定前先剥注释，避免注释里写一句 `void main()` 就被误杀。

同理，**永不拒绝 `precision` 重声明** —— 它在 ANGLE 下合法，`70s-melt-color` 依赖它。（`scripts/lib/glsl-wrap.js` 的头注释把它和包装器冲突归为一类，那是错的。）

还要说清楚：浏览器那道是**体验护栏，不是安全控制**，直接 POST 一下就绕过去了。服务端形态校验才是兜底。两边各管各的，都不能省。

写侧规则也**不能套到读路径上**：规则会演进，收紧它会把历史合法记录变成「内容已损坏」，而读取是唯一的恢复路径。

## 为什么发布可用性探测要看「状态码 + 响应体」

静态托管没有 `/api/shader`，所以启动时探一次 `GET /api/shader`（不带 `id`，两个后端都回 400 + JSON，零副作用），据此决定发布按钮是否置灰。

结论需要**两者都看**：

- 只看状态码 → 被 SPA fallback 骗过（未知路径重写成 `index.html`，200 HTML）。
- 只看「是不是 JSON」 → 被网关骗过（有网关对未知路由回 **404 + JSON**，实测于 `cnb.run` 开发域名）。

真实后端对该探测的回答是 **400 + JSON**（`api/shader.js`：缺 `id` → 400 `{error}`），所以 **404 = 这条路由没人接**。

## 为什么存储键用内容哈希

`contentKey(code)` = `base62(sha256(code))` 前 8 位。

真正的价值不是省空间，而是**改变存储耗尽攻击的成本模型**：

| 攻击 | 随机 ID | 内容寻址后 |
|---|---|---|
| 10000 个 IP 各发同一份 512 KB | 存 10000 份 = 4.9 GB | **存 1 份** |
| 10000 个 IP 各发不同 512 KB | 存 4.9 GB | 存 4.9 GB，但攻击者得真上传 5 GB |

洪水从「按请求数计费」变成「按不同内容的字节数计费」—— 这是把 O(便宜) 的攻击改成 O(昂贵)，比任何配额都有效。所以**字节预算仍然保留，两者正交**：内容寻址让攻击变贵，字节预算让它有界。

两个必须小心的地方：

- **8 位键只取了哈希的低 47.5 bit**，5000 条时碰撞概率约 6e-8。随机 ID 碰撞能被检出并重试，内容哈希碰撞却会被误判成「同一份内容」—— 用户会拿到播放错误 shader 的链接。所以每次写入都要**取出内容比对**：相同才去重，不同则判定碰撞、退回随机 ID（`assignId()` 已处理）。
- **ID 由内容派生后，未授权读取反而更难**：攻击者要猜的是完整 shader 源码，熵远高于 47.5 bit。代价是多了一个「确认某份已知内容是否存在」的 oracle —— 考虑到 ID 本来就是为了分享出去的，这个代价可忽略。

## 为什么写入限制只是减速带

Serverless 每个实例独立计数、跨实例不共享，真正生效的上限约等于「阈值 × 同时存活的实例数」；Vercel 侧 IP 取自 `x-forwarded-for`，理论上可伪造。要真正拦 abuse，请在平台层配（Vercel Firewall / Netlify 自带限速）。

相关常量的取值理由：

- **512 KB 按 UTF-8 字节、不按 `String.length`** —— 否则中文注释能「偷渡」数倍体积。
- **`MAX_STORED_BYTES` = 2× code 上限 + 16 KB** —— JSON 转义几乎能让字节翻倍（每个换行/引号/反斜杠变成 2）。
- **写入与读取必须量同一个字节数**（都走 `serialize()`）。量法不一致会出现「存得进去、读不出来」的记录：GET 永久 500，且去重失效（读不出的内容被当成碰撞，每次重投都再存一份）。
- **存储条目上限之外还要字节上限** —— 只按条数算不够：5000 × 512 KB = 2.44 GiB，函数会先 OOM 再谈 503。
- **`validateCode` 先查体积再查形态** —— 600 KB 的载荷报「too large」，而不是误导性的「missing mainImage」。

## 为什么编译失败是黑屏（不是 bug）

`applyShader()` → `createProgram()` 在编译**前**先删掉旧 `program`，所以编译/链接失败会留下 `program === null`，`render()` 跳过绘制 → 黑屏。这是刻意的「你的改动没生效」信号。

不要「修」成编译到临时 program、成功后替换：那样编辑器关闭后上一个 shader 仍在动，失败的编辑看起来是成功的。

## 为什么 `js/` 不用 ES module

`file://` 下模块请求会被 CORS 拦掉，而这个页面必须能双击直接打开。代价是没有 `import`/`export`，模块之间靠**加载顺序 + 共享全局词法作用域**通信 —— 所以 `index.html` 底部那份 `<script>` 列表就是依赖图。

## 为什么 `?js=` 有响应头要求

`<script src>` 绕过 CORS 但绕不过 CORP，一个可用目标需要同时满足三个响应头；源码托管站的 raw 接口基本都不满足。实测矩阵见 [external-js.md](external-js.md)。
